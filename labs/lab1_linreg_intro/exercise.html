Lab 1 Exercise - Linear Regression Challenge

Author

Erez Buchweitz/Lucas Schwengber/Josh Davis

You are given three files:

  • X_train.npy
  • y_train.npy
  • X_test.npy

You may download and read them like this:

import numpy as np
import urllib.request

urllib.request.urlretrieve('https://stat154.berkeley.edu/spring-2026/datasets/linreg/X_train.npy', '{path}/X_train.npy')    
urllib.request.urlretrieve('https://stat154.berkeley.edu/spring-2026/datasets/linreg/X_test.npy', '{path}/X_test.npy')
urllib.request.urlretrieve('https://stat154.berkeley.edu/spring-2026/datasets/linreg/y_train.npy', '{path}/y_train.npy')

X_train = np.load("{path}/X_train.npy")
X_test = np.load("{path}/X_test.npy")
y_train = np.load("{path}/y_train.npy")

There are two data sets, (X_train, y_train) and (X_test, y_test), which are independent and identically distributed. However, I have hidden y_test from you. Your task is to make the best predictions of y_test possible based on the training data and on X_test.

1 How to submit predictions

You will submit a binary .npy file containing a numpy array (one-dimensional), whose length is the same as the number of rows in X_test, that will comprise the predictions of y_test. You can save an array to file like this:

import numpy as np

np.save("pred_{codename}.npy", pred)

The name of the file should be "pred_{codename}.npy" where {codename} is a secret codename of your group’s choosing, that you will be able to use later to identify your submission in the leaderboard. The file, alongside your code, should be submitted to GradeScope.

2 How your predictions will be scored

Your predictions will be compared against the real y_test using average squared error:

\[ \text{your loss} = \frac{1}{N}\sum_{n=1}^N (y_n - \text{pred}_n)^2. \]

A leaderboard will be published with every group’s codename alongside its loss on the test set, ranked from low to high. No other identifying information will be shared, so no other student will be able know your rank on the leaderboard. The leaderboard is for your own benefit! The group with the lowest test loss is the winner.

3 Allowed methods to use

You are permitted to use only methods which you have learned in the lectures or labs, or that are adjacent to them. This includes, for example, ordinary least squares and feature engineering. Any use of significantly more advanced learning algorithms might result in disqualification and zero grade.

4 Timeline

The challenge will last two consecutive lab sessions, starting from the lab session on Sep 14th and ending at the end of the lab session on Sep 21st. You will submit predictions at two times:

1 - Until 9 PM on Sep 14th. 2 - Until 9 PM Sep 21st.

A leaderboard will be after each submission deadline.

You are not required to work on the challenge outside lab sessions, however it is encouraged. This is for your benefit! The more time you spend working with data you will find you get more out of this course.

5 How you will be graded

The grading will be based on completing. We expect at least the following to have been completed across both sessions:

1 - Data loading, evaluation pipeline implemented, raw features fit and evaluation, raw feature diagnostic plots
2 - Non-linear individual features visualized and tested, pairwise interactions visualized and tested.

Your combined submissions must have all of these, and you should make progress on each lab. But when the specific steps are accomplished is up to you. Once they are completed you must devote the time to improve your model performance. It is theoretically possible to achieve 0 error on this problem: there is a deterministic ground-truth function, it is a linear combination of non-linear functions of individual features and at most pairwise interactions (possibly involving non-linearities).

Your rank on the leaderboard will not factor into your grade in any way.

6 LLM usage policy

You may use auto-completion for filling out small code snippets (affect around 2-3 lines of code) and documenting your code. Small code snippets are things like “add a label for the axis of the plot”, “change the color of the points”, “add an argument for the number of interactions in the fit”. These are small code operations which do not involve significant planning nor automated changes to the logic of the code without your supervision. All edits must be verified and accepted manually, and you should make sure you know what the code is doing.

Things that are explicitly not allowed are major edits to the code (affect > 10 lines) and ones which involve automating huge parts of the development of the logic structure of your analysis. For example, “write a function to extract features from the data”, or “run a test set validation loop and report the best model”.

Delegate to language models only things which you know exactly how you would have done it yourself or would be comfortable googling/asking for help from someone who already took the course/knows how to code, but who cannot do the learning for you.
