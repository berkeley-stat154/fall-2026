Learning goals

By the end of this lab you should be able to:

  1. Explain a shallow ReLU network as a sum of hinges, and why composing layers multiplies the number of linear pieces.
  2. Read and use a PyTorch training loop (cross-entropy, minibatches, optimizer steps), and diagnose a bad learning rate from the training loss.
  3. Interpret the last layer of a classifier as a logistic regression on features (an embedding) that the network learns.
  4. Explain why fully connected networks ignore where pixels are, and what this costs them on images.
  5. Explain how a convolutional layer works (weight sharing, channels, pooling), and count the parameters of a CNN.
  6. Use a validation set to detect overfitting, choose the number of epochs, and compare architectures.
  7. Make a CNN more robust to small shifts, through its architecture (depth and pooling) or with data augmentation.

1 Neural networks as functions

1.1 A shallow network is a sum of hinges

The simplest neural network takes a scalar input \(x\) and returns a scalar output (Prince 2023, sec. 3.1): \[ f(x) = \phi_0 + \sum_{d=1}^{D} \phi_d \, a(\theta_{d0} + \theta_{d1} x), \qquad a(z) = \mathrm{ReLU}(z) = \max(0, z). \] As a diagram, with \(D = 3\) hidden units:

Layer 1. Each hidden unit computes \(\theta_{d0} + \theta_{d1} x\) and applies the ReLU: \[ \begin{aligned} h_1 &= \mathrm{ReLU}(1 + 1 \cdot 1.5) = \mathrm{ReLU}(2.5) = 2.5, \\ h_2 &= \mathrm{ReLU}(-1 + 2 \cdot 1.5) = \mathrm{ReLU}(2) = 2, \\ h_3 &= \mathrm{ReLU}(1 + (-1) \cdot 1.5) = \mathrm{ReLU}(-0.5) = 0. \end{aligned} \]

Layer 2. The output is \(\phi_0\) plus the weighted sum of the hidden units: \[ f(1.5) = \phi_0 + \phi_1 h_1 + \phi_2 h_2 + \phi_3 h_3 = 0.5 + 1 \cdot 2.5 + (-2) \cdot 2 + 0.5 \cdot 0 = -1. \]

Hidden unit 3 is off at \(x = 1.5\): its input \(1 - 1.5\) is negative, so the ReLU outputs \(0\) and \(\phi_3\) has no effect on \(f(1.5)\). Doing this for every \(x\) gives the function on the right. Its slope changes at \(x = -1\), \(0.5\) and \(1\) (blue lines), where one of the hidden units switches on or off.

Each of the \(D\) hidden units \(h_d(x) = a(\theta_{d0} + \theta_{d1} x)\) is a “hinge”: it is zero on one side of its joint \(x = -\theta_{d0}/\theta_{d1}\) and linear on the other. So \(f\) is piecewise linear with at most \(D\) joints. It is a linear spline, as in lab 2, except that the knots are learned from the data together with the coefficients.

Below we fit networks with \(D = 3\), \(10\) and \(50\) hidden units to noisy data by least squares, with gradient descent (Section 2.2).

def target(x):
    return np.sin(2 * x) + 0.3 * x**2


rng = np.random.default_rng(0)
x_reg = rng.uniform(-3, 3, size=200)
y_reg = target(x_reg) + 0.2 * rng.standard_normal(200)
X_reg = torch.tensor(x_reg, dtype=torch.float32).reshape(-1, 1)    # PyTorch wants an (n, p) array of floats
Y_reg = torch.tensor(y_reg, dtype=torch.float32).reshape(-1, 1)


class ShallowNet(nn.Module):
    """f(x) = phi_0 + sum_d phi_d ReLU(theta_d0 + theta_d1 x), with D hidden units."""

    def __init__(self, D):
        super().__init__()
        self.hidden = nn.Linear(1, D)    # the thetas: weight (D, 1) holds the slopes theta_d1, bias (D,) the theta_d0
        self.output = nn.Linear(D, 1)    # the phis: weight (1, D) holds phi_1, ..., phi_D, bias (1,) holds phi_0

    def hidden_units(self, x):
        return torch.relu(self.hidden(x))

    def forward(self, x):
        return self.output(self.hidden_units(x))

    def joints(self):
        """The points x = -theta_d0 / theta_d1 where each hidden unit switches on or off."""
        return (-self.hidden.bias / self.hidden.weight[:, 0]).detach().numpy()


def fit_least_squares(model, X, Y, n_steps=3000, lr=0.01):
    """Minimize the mean squared error by full-batch gradient descent (with the Adam optimizer)."""
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    for step in range(n_steps):
        optimizer.zero_grad()
        loss = ((model(X) - Y) ** 2).mean()
        loss.backward()
        optimizer.step()
    return model


torch.manual_seed(1)
shallow_nets = {D: fit_least_squares(ShallowNet(D), X_reg, Y_reg) for D in [3, 10, 50]}

1.2 Reading the parameters off the picture

Every parameter has a geometric meaning. Here is the \(D = 3\) network split into its weighted hinges \(\phi_d h_d(x)\):

Plotting code 
net = shallow_nets[3]
with torch.no_grad():
    H = net.hidden_units(X_grid).numpy()     # (600, D): the hidden units h_d(x) on the grid
    phi = net.output.weight[0].numpy()       # (D,): the output weights phi_d
    phi0 = net.output.bias.item()

fig, ax = plt.subplots(figsize=(6, 3.6))
for d in range(H.shape[1]):
    ax.plot(x_grid, phi[d] * H[:, d], lw=1.5, label=f"$\\phi_{d + 1} h_{d + 1}(x)$")
ax.plot(x_grid, phi0 + H @ phi, "k", lw=2.5, label="$f(x) = \\phi_0 + \\sum_d \\phi_d h_d(x)$")
ax.set_xlabel("$x$")
ax.legend(fontsize=9)
plt.show()
  • Unit \(d\) has its joint at \(x = -\theta_{d0}/\theta_{d1}\). It is on to the right of the joint if \(\theta_{d1} > 0\), and to the left if \(\theta_{d1} < 0\).
  • Crossing the joint of unit \(d\) from left to right changes the slope of \(f\) by \(\phi_d |\theta_{d1}|\).
  • \(\phi_0\) moves the whole function up or down.

So to draw a piecewise linear function, put one hidden unit at each kink, with the output weight that changes the slope by the right amount. For example, \(\mathrm{ReLU}(x - 1) - \mathrm{ReLU}(x - 2)\) is \(0\) up to \(x = 1\), rises with slope \(1\) up to \(x = 2\), and stays at \(1\) after. Training finds such parameters by itself, starting from random values; with another seed, two units might share a joint, or a unit might be zero on all the data (a “dead” unit).

With enough hidden units, a shallow network can approximate any continuous function on a bounded set as closely as we want: this is the universal approximation theorem (Cybenko 1989; Hornik 1991; Leshno et al. 1993; Prince 2023, sec. 3.2). It does not say how many units are needed, or whether training finds them.

1.3 Depth multiplies the linear pieces

A deep network applies several layers of hidden units in sequence: the output of each layer is the input of the next (Prince 2023, ch. 4). To see why this helps, compose two shallow networks \(f_1\) and \(f_2\) with three hidden units each into \(f_2(f_1(x))\) (Prince 2023, sec. 4.1). Below, \(f_1\) is a zigzag that sweeps the interval \([0, 1]\) three times as \(x\) goes from \(0\) to \(1\).

def relu(z):
    return np.maximum(z, 0)


def f1(x):
    """Shallow network with 3 hidden units: a zigzag that sweeps [0, 1] three times as x goes from 0 to 1."""
    return 3 * relu(x) - 6 * relu(x - 1 / 3) + 6 * relu(x - 2 / 3)


def f2(u):
    """Another shallow network with 3 hidden units."""
    return -0.5 + 2 * relu(u) - 5 * relu(u - 0.4) + 4 * relu(u - 0.75)
Plotting code 
x = np.linspace(0, 1, 1201)
fig, axes = plt.subplots(1, 3, figsize=(13, 3.3))
axes[0].plot(x, f1(x), color="C0")
axes[0].set(title="$f_1(x)$: 3 pieces", xlabel="$x$")
axes[1].plot(x, f2(x), color="C2")
axes[1].set(title="$f_2(u)$: 3 pieces", xlabel="$u$")
axes[2].plot(x, f2(f1(x)), color="C1")
axes[2].set(title="$f_2(f_1(x))$: 9 pieces", xlabel="$x$")
plt.show()

Each time \(f_1\) sweeps \([0, 1]\), the composition traces out all of \(f_2\), so \(f_2(f_1(x))\) has \(3 \times 3 = 9\) linear pieces from 6 hidden units. A shallow network with \(D\) hidden units has at most \(D\) joints, so at most \(D + 1\) pieces. Each additional layer of this kind multiplies the number of pieces by 3, but adds only 3 hidden units. In general, the number of linear regions can grow exponentially with depth, but only polynomially with width (Montúfar et al. 2014; Prince 2023, sec. 4.5); trained networks do not necessarily use that many regions (Hanin and Rolnick 2019).

With an input vector \(\boldsymbol{x}\), layer \(k\) computes \(\boldsymbol{h}_{k+1} = a(\boldsymbol{\beta}_k + \boldsymbol{\Omega}_k \boldsymbol{h}_k)\), with \(a\) applied to each coordinate (Prince 2023, sec. 4.4). In PyTorch, this is an nn.Linear layer followed by nn.ReLU().

2 Classifiers learn their own features

2.1 Logistic regression on learned features

For \(K\) classes, the network outputs \(K\) logits \(\ell_1(\boldsymbol{x}), \ldots, \ell_K(\boldsymbol{x})\), which the softmax turns into probabilities, \(\mathbb{P}_{\,}\left(y = k \mid \boldsymbol{x}\right) = \exp(\ell_k(\boldsymbol{x})) / \sum_{j=1}^K \exp(\ell_j(\boldsymbol{x}))\). It is fit by minimizing the cross-entropy \(-\sum_{n=1}^N\log \mathbb{P}_{\,}\left(y_n \mid \boldsymbol{x}_n\right)\), the negative log-likelihood (Prince 2023, sec. 5.5); for \(K = 2\), this is the logistic loss from lab 7.

Split the network in two: the first layers compute an embedding \(\boldsymbol{z}(\boldsymbol{x}) \in \mathbb{R}^q\), and the last layer is linear, \(\ell_k(\boldsymbol{x}) = \beta_k + \boldsymbol{w}_k^\intercal\boldsymbol{z}(\boldsymbol{x})\). So the last layer is a logistic regression whose features are learned along with its coefficients. Here is a data set where logistic regression on the raw features fails:

Data and logistic regression 
from sklearn.datasets import make_circles

A straight line cannot separate the circles, but a threshold on \(x_1^2 + x_2^2\) can. Does a network find such a feature by itself? Ours has two hidden layers of 16 units and a 2-dimensional embedding, so that we can plot it.

class CircleNet(nn.Module):
    def __init__(self, hidden=16, embed_dim=2, n_classes=2):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Linear(2, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, embed_dim),          # the embedding z(x)
        )
        self.classifier = nn.Linear(embed_dim, n_classes)    # logistic regression on z(x)

    def embedding(self, x):
        return self.encoder(x)

    def forward(self, x):
        return self.classifier(self.embedding(x))      # the logits

2.2 Training with gradient descent

Training minimizes the loss \(\mathscr{L}(\phi)\) over all the parameters \(\phi\) by gradient descent, \(\phi \leftarrow \phi - \alpha \nabla_\phi \mathscr{L}(\phi)\), with a learning rate \(\alpha\) (Prince 2023, ch. 6).

  • Backpropagation computes all the partial derivatives at once with the chain rule, at about the cost of evaluating the network (Rumelhart et al. 1986; Prince 2023, ch. 7). In PyTorch, loss.backward() stores them in p.grad for every parameter p.
  • Stochastic gradient descent (SGD) uses the gradient on a small random minibatch instead of the full data set: the steps are noisy but cheap. One pass over all the minibatches is an epoch (Prince 2023, sec. 6.2).

Every PyTorch training loop has the same five steps:

X_circ_t = torch.tensor(X_circ, dtype=torch.float32)
y_circ_t = torch.tensor(y_circ)                # class labels as integers 0, ..., K - 1
circle_data = torch.utils.data.TensorDataset(X_circ_t, y_circ_t)


def train_circle_net(lr, optimizer_class=torch.optim.Adam, embed_dim=2, n_epochs=50, batch_size=32, seed=0):
    torch.manual_seed(seed)
    net = CircleNet(embed_dim=embed_dim)
    loader = torch.utils.data.DataLoader(circle_data, batch_size=batch_size, shuffle=True)
    optimizer = optimizer_class(net.parameters(), lr=lr)
    epoch_losses = []
    for epoch in range(n_epochs):
        for xb, yb in loader:                     # one epoch = one pass over all the minibatches
            optimizer.zero_grad()                 # 1. reset the gradients from the previous step
            logits = net(xb)                      # 2. forward pass
            loss = F.cross_entropy(logits, yb)    # 3. softmax + negative log-likelihood, averaged over the batch
            loss.backward()                       # 4. backpropagation: fills p.grad for every parameter p
            optimizer.step()                      # 5. gradient step
        with torch.no_grad():                     # no gradients needed to evaluate the loss
            epoch_losses.append(F.cross_entropy(net(X_circ_t), y_circ_t).item())
    return net, epoch_losses

With \(10^{-4}\) the loss barely moves in 50 epochs, and with \(1\) it never settles. The learning rate is usually the first hyperparameter to tune (Prince 2023, sec. 6.5), and good values depend on the optimizer:

  • Plain SGD moves each parameter by \(\alpha\) times its partial derivative. If \(\alpha\) is too small, training crawls. If it is too large, each step overshoots the minimum in the steep directions and lands where the gradient is even larger; the parameters blow up and the loss becomes nan (“not a number”).
  • Adam divides each partial derivative by a running estimate of its typical size, so each parameter moves by roughly \(\alpha\) per step, whatever the scale of the gradient (Kingma and Ba 2015; Prince 2023, sec. 6.4). Values around \(10^{-3}\) work for many problems, while good learning rates for SGD vary more from problem to problem and are often larger.

These are training losses: they tell us whether the optimization works, not whether the network generalizes.

So a 1-dimensional embedding would do. With a single feature \(z(\boldsymbol{x})\), the last layer can only set a threshold, predicting one class above a cutoff and the other below; that works as long as the first layers make \(z(\boldsymbol{x})\) larger on one circle than on the other. In general, the embedding needs enough dimensions for the classes to become linearly separable in it.

def evaluate(model, loader, transform=None):
    """Average cross-entropy and accuracy of the model on a data set."""
    model.eval()
    total_loss, n_correct, n = 0.0, 0, 0
    with torch.no_grad():
        for xb, yb in loader:
            if transform is not None:
                xb = transform(xb)
            xb, yb = xb.to(device), yb.to(device)
            logits = model(xb)
            total_loss += F.cross_entropy(logits, yb, reduction="sum").item()
            n_correct += (logits.argmax(dim=1) == yb).sum().item()
            n += len(yb)
    return total_loss / n, n_correct / n


def train(model, train_loader, n_epochs, lr=1e-3, weight_decay=0.0, transform=None, verbose=True):
    """Train with Adam. After each epoch, record the training loss (the average of the minibatch losses during
    the epoch, which is cheap to compute but lags a little behind) and the validation loss and accuracy."""
    model.to(device)      # the GPU, if there is one
    optimizer = torch.optim.Adam(model.parameters(), lr=lr, weight_decay=weight_decay)
    history = {"train_loss": [], "val_loss": [], "val_acc": []}
    for epoch in range(n_epochs):
        model.train()      # model.train() and model.eval() matter for layers like dropout; a good habit
        total_loss, n = 0.0, 0
        for xb, yb in train_loader:
            if transform is not None:
                xb = transform(xb)
            xb, yb = xb.to(device), yb.to(device)
            optimizer.zero_grad()
            loss = F.cross_entropy(model(xb), yb)
            loss.backward()
            optimizer.step()
            total_loss += loss.item() * len(yb)
            n += len(yb)
        val_loss, val_acc = evaluate(model, val_loader, transform)
        history["train_loss"].append(total_loss / n)
        history["val_loss"].append(val_loss)
        history["val_acc"].append(val_acc)
        if verbose:
            print(f"  epoch {epoch + 1:2d}: training loss {total_loss / n:.3f}, "
                  f"validation loss {val_loss:.3f}, validation accuracy {val_acc:.1%}")
    return history

Each weight belongs to one pixel position. In logistic regression, the logit of class \(k\) is \(\beta_k + \boldsymbol{w}_k^\intercal\boldsymbol{x}\), so we can draw \(\boldsymbol{w}_k\) as a \(28 \times 28\) image: red where ink pushes the prediction towards class \(k\), blue where it pushes away.

Each weight image is a template at a fixed position: the 0 is a red ring with a blue center, the 1 a red vertical stroke. The hidden units of the fully connected network can be drawn the same way, and they are tied to fixed positions too.

Nothing says which pixels are neighbors. If we scramble the pixels, with the same permutation for every image, the digits become noise to us but not to the network: scrambling only permutes the columns of its first weight matrix, so it can learn the scrambled digits just as well. It does not use the fact that nearby pixels are related.

A shifted digit is a new input. A digit moved by 3 pixels puts its ink on other weights, so the network has to learn from examples, separately at every position, that it is the same digit. In section 5, its accuracy drops to about 50% on test digits shifted by 3 pixels.

The first layer grows with the image. It has one weight per pixel and hidden unit: about 100,000 here, but 19 million for a \(224 \times 224\) color image with the same 128 hidden units.

Convolutional networks build these facts about images into the network.

4 Convolutional networks

4.1 The convolution operation

A convolutional layer builds the structure of images into the network (Prince 2023, ch. 10). A small grid of weights \(\boldsymbol{\omega}\), the kernel, slides over the image: output pixel \((i, j)\) is the weighted sum of the input patch around \((i, j)\) (Prince 2023, secs. 10.2–10.3). For a \(3 \times 3\) kernel, \[ z_{ij} = \sum_{m=1}^{3} \sum_{n=1}^{3} \omega_{mn} \, x_{i+m-2, j+n-2}, \] where pixels outside the image count as zero (zero padding), so the output has the size of the input. PyTorch’s F.conv2d computes exactly this. Two ways to see a convolution:

  • A fully connected layer in which each output depends on only 9 nearby pixels, with the same 9 weights (and one bias) at every position: weight sharing.
  • Template matching with a \(3 \times 3\) template: the output is large where the patch looks like the kernel. A kernel with positive weights along a line and negative weights around it responds to strokes in that direction.

Below are two hand-designed edge detectors and a blur. A convolutional network learns its kernels from the data.

4.2 The layers of a CNN

A CNN is built from five kinds of layers (Prince 2023, ch. 10):

  • Convolution (nn.Conv2d): applies several kernels to its input, and each kernel produces one output image, called a channel or feature map, that is large where the input looks like the kernel. Each kernel looks at all the input channels at once, so a layer from \(C_{\text{in}}\) to \(C_{\text{out}}\) channels with \(K \times K\) kernels has \(K^2 C_{\text{in}} C_{\text{out}} + C_{\text{out}}\) parameters, whatever the size of the image. Because the same kernels are used at every position, a pattern is detected wherever it appears: shifting the input shifts the feature maps by the same amount (translation equivariance).
  • ReLU (nn.ReLU): replaces every negative number by zero, as in section 1. Without it, the stacked layers would collapse into a single linear function.
  • Max pooling (nn.MaxPool2d(2)): keeps the largest value in each \(2 \times 2\) block of each channel, which halves the height and width. The next layers then see larger regions of the input (edges, then pieces of strokes, then whole digits), and small shifts of the input matter less.
  • Flatten (nn.Flatten): lines up the \(C \times H \times W\) numbers of the last feature maps into one vector of length \(CHW\), so that fully connected layers can follow.
  • Fully connected (nn.Linear): as in sections 1 and 2, each output is a weighted sum of all the inputs plus a bias, so a layer from \(n_{\text{in}}\) to \(n_{\text{out}}\) units has \((n_{\text{in}} + 1) \, n_{\text{out}}\) parameters. The last one outputs the 10 logits: it is a logistic regression on the features computed by the layers before it.

ReLU, pooling and flatten have no parameters. Our CNN repeats convolution, ReLU and pooling three times, with more channels as the images get smaller, and ends with two fully connected layers. nn.Sequential chains the layers, and print_shapes prints the output shape and number of parameters of each layer:

5.2 Overfitting and early stopping

Here none of the networks overfits: the training and validation losses are close, and still going down. With less data or many more epochs, the training loss keeps going down as the network memorizes the training images, while the validation loss reaches a minimum and then goes back up. Early stopping keeps the network from the epoch with the lowest validation loss (Prince 2023, sec. 9.3.1): the number of epochs is a hyperparameter, chosen with the validation set. More generally, the validation set is how we choose between models, for example between architectures, while the test set stays untouched until the end.

The validation loss can go up a lot while the validation accuracy stays almost flat. Once the training data is fit perfectly, training keeps pushing the predicted probabilities towards 0 and 1. The predicted classes barely change, but the network becomes more confident, including in its mistakes, and the cross-entropy \(-\log \mathbb{P}_{\,}\left(y \mid \boldsymbol{x}\right)\) of a confident mistake is large.

5.3 Robustness to shifts

def shift(images, dx=0, dy=0):
    """Translate images (last two dimensions 28 x 28) by dx pixels right and dy pixels down, filling with zeros."""
    out = torch.roll(images, shifts=(dy, dx), dims=(-2, -1))
    if dy > 0:
        out[..., :dy, :] = 0
    if dy < 0:
        out[..., dy:, :] = 0
    if dx > 0:
        out[..., :, :dx] = 0
    if dx < 0:
        out[..., :, dx:] = 0
    return out


def shift_accuracy(model, k):
    """Test accuracy on images shifted by k pixels, averaged over the four directions."""
    return np.mean([evaluate(model, test_loader, transform=lambda imgs: shift(imgs, dx, dy))[1]
                    for dx, dy in [(k, 0), (-k, 0), (0, k), (0, -k)]])


shifts = [0, 1, 2, 3, 4]
fig, ax = plt.subplots(figsize=(5.5, 3.5))
for name, model in models.items():
    accs = [shift_accuracy(model, k) for k in shifts]
    ax.plot(shifts, accs, "o-", label=name)
    print(f"{name:<20} " + ",  ".join(f"shift {k}: {a:.1%}" for k, a in zip(shifts, accs)))
ax.set(xlabel="shift (pixels)", ylabel="test accuracy", xticks=shifts)
ax.legend()
plt.show()

At a 3-pixel shift, logistic regression and the fully connected network get only about a third and a half of the test images right, while the CNN still gets nearly nine in ten. Convolutions and pooling make the CNN robust to small shifts, but not invariant: it was trained on centered digits, and its fully connected layers depend on location.

5.4 What convolutions assume

The CNN’s advantages rest on an assumption: nearby pixels are related, and a local pattern (an edge, the end of a stroke) means the same thing wherever it appears. This holds for images, so sharing weights across positions costs nothing. If we scrambled the pixels as in section 3, the fully connected network would not notice, but the CNN’s \(3 \times 3\) patches would become sets of unrelated pixels from all over the image, and it would lose its advantage.
